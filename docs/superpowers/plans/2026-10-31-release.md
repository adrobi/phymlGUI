# Релиз — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** по тегу `v*` GitHub Actions собирает Windows-zip и Linux-AppImage со всеми программами анализа, проверяет их и создаёт черновик релиза.

**Architecture:** приложение получает небольшой слой кроссплатформенности; сторонние программы описаны в одном манифесте по платформам и собираются/скачиваются скриптами из `packaging/`; один `release.yml` проходит тесты → инструменты → упаковка → дымовые тесты → черновик.

**Tech Stack:** Python ≥ 3.11, PySide6, PyInstaller ≥ 6, appimagetool, MSYS2 UCRT64, autotools + OpenMPI, GitHub Actions (`windows-latest`, `ubuntu-22.04`).

**Spec:** [docs/superpowers/specs/2026-10-31-release-design.md](../specs/2026-10-31-release-design.md)

## Global Constraints

- `phyml_core` не импортирует PySide6.
- Тесты не трогают настоящий конфиг/историю пользователя; весь набор зелёный на Windows и ubuntu-22.04.
- Задачи 1–3 и 6 (Linux) выполняются без субагентов (пожелание пользователя).
- Релиз по тегу — только **черновик**; `workflow_dispatch` ничего не публикует; push и теги — только с явного «да» пользователя.
- Каждый скачиваемый файл закреплён SHA256 в `packaging/third_party.json`; проверка до записи в `dest`.
- Ветка `release`; сообщения коммитов — английское предложение + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **AppImage на машине без OpenMPI** — включённый MPI даёт понятную ошибку до старта, последовательный режим работает. Тест: Task 2 (`test_validate_mpirun_missing_on_linux`).
2. **Конфиг, перенесённый с Windows на Linux** (`mpirun_path: "mpiexec"`, пути `C:\...`) — окно открывается, `mpiexec` → `mpirun`, неверные пути дают ошибку «не найден», а не падение. Тест: Task 2 (`test_windows_config_loads_on_linux`).
3. **Только-чтение папки приложения в AppImage** — настройки уходят в `~/.config/phymlGUI` (или `$XDG_CONFIG_HOME`). Тест: Task 2 (`test_detect_falls_back_to_xdg_on_linux`).
4. **Пути с пробелами и кириллицей в Linux** (`/home/user/Мои данные/`). Тест: Task 3 — существующий `test_run_in_cyrillic_dir_with_spaces` должен проходить на ubuntu.
5. **Тег не того формата / повторный запуск по тегу** — workflow падает до сборки, черновик не дублируется. Тест: Task 8 (`test_release_tag_validation` для `packaging/release_meta.py`).
