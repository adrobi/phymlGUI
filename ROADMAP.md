# phymlGUI — дорожная карта доработок (v1.3+)

Порядок этапов выстроен по логике зависимостей: сначала каркас интерфейса
(на нём держится всё остальное), затем самый востребованный виджет
(просмотрщик деревьев), затем UX-слой поверх нового каркаса, и только потом
аналитические фичи, которые требуют абстракций в ядре. Инфраструктурные
задачи размечены «параллельно» — их можно втыкать между этапами.

## Принятые решения по интерфейсу (из обсуждения)

- **Структура:** двухпанельное окно — слева навигация (недавние файлы,
  пресеты, история запусков), справа рабочая область.
- **Темы:** светлая и тёмная с переключателем и запоминанием в конфиге,
  единый акцентный цвет в обеих.
- **Результаты:** вкладки прямо в главном окне — Журнал | Дерево |
  Статистика | Сводка; дерево больше не всплывает отдельным диалогом.
- **Геометрия:** ориентир — FullHD 1920×1080 при масштабе 100% (допустимо
  125–150%); обязательная graceful-деградация до 1366×768: минимальные
  размеры окна, прокрутка блока параметров, панель скрывается.
- **Болевые точки к закрытию:** бедный просмотрщик деревьев, отсутствие
  истории/недавних файлов, «простыня» в журнале, теснота текущего окна.

## Этап 1 — Фундамент нового UI (v1.3)

Каркас, к которому потом прикручивается всё. Без этого этапа остальные
фичи пришлось бы ставить на старый layout и переделывать дважды.

1.1 **Система тем.** QSS-темы `light.qss` / `dark.qss` + переменная
    акцентного цвета; переключатель в тулбаре/меню, выбор сохраняется в
    `phyml_config.json`. Акцент — на действиях (Run/Cancel), поддержках
    ветвей, ссылках истории.
1.2 **Двухпанельный каркас.** `QSplitter`: слева панель навигации
    (Недавние | Пресеты | История — пока заглушки списков), справа
    рабочая область. Панель сворачивается до иконок и полностью
    прячется на узких экранах; ширина запоминается.
1.3 **Вкладки результатов.** Внизу правой области `QTabWidget`:
    Журнал / Дерево / Статистика / Сводка. Дерево — встраиваемый виджет
    (бывший `TreeViewerDialog` без диалога), автоматически переключаться
    на вкладку по завершению прогона (настраивается).
1.4 **Адаптивная геометрия.** Минимальный размер окна под 1366×768;
    блок параметров — в `QScrollArea`; вкладки результатов —
    скрываемые/закрываемые; проверка на 100%/125%/150% DPI.
    Приоритет места: журнал и дерево, параметры — вторичны.
1.5 **Структурированный журнал.** Роли строк с цветом (ошибка — красный,
    успех — зелёный, команды — моно, разделы файлов пакета — жирный),
    фильтр по типу, поиск по тексту, пауза автоскролла при ручной
    прокрутке. Реализация: `QListView` + модель вместо плоского `QTextEdit`.
1.6 **Полировка путей.** Группа путей сжимается: единая строка
    «движок» с дропдауном (PhyML / IQ-TREE — задел на этап 4),
    выбор файла/папки через одну умную кнопку, Drag&Drop прямо в поле.

## Этап 2 — Просмотрщик деревьев (v1.4)

Самая видимая пользователю часть после каркаса.

2.1 **Экспорт:** PNG, SVG, PDF (векторный) + сохранение Newick.
2.2 **Раскладки:** прямоугольная, сланцевая (slanted), круговая;
    переключатель и запоминание.
2.3 **Интерактив:** клик по кладе — свернуть/развернуть; подсветка ветвей
    по порогу поддержки (слайдер «показывать ≥ N%»); зум к выбранной кладе.
2.4 **Outgroup:** выбор таксона из списка → рерутинг дерева на лету
    (Bio.Phylo `tree_with_outgroup` / root_with_outgroup).
2.5 **Оформление:** шкала ветвей (scale bar), размер и поворот подписей,
    легенда порога поддержки; параметры рендера учитывают тему (тёмная —
    светлые линии).

## Этап 3 — История и UX пайплайна (v1.4–1.5)

Наполняет левую панель реальным содержанием.

3.1 **История запусков.** Локальный JSON (`phyml_history.json`):
    дата, вход(ы), движок/модель/поддержка, статус, длительность, пути
    к результатам. Клик по записи — открыть дерево/статистику; повтор —
    заполнить форму параметрами того прогона. Ограничение по глубине
    (например, 200 записей).
3.2 **Недавние файлы и папки** — верх списка пути, быстрый выбор.
3.3 **Drag&Drop** FASTA-файла или папки в окно → заполнение пути запуска.
3.4 **Пресеты параметров:** встроенные («Быстрый скрининг» — NNI+aLRT,
    «Публикация» — SPR/BEST+bootstrap 1000) и пользовательские;
    сохранение/загрузка/удаление, живут в левой панели.
3.5 **Прогресс пакета:** список файлов очереди со статусами
    (в ожидании / выполняется / OK / FAIL / отменён), общий прогресс-бар,
    после завершения — кнопка «Повторить только неудавшиеся».
3.6 **Кнопка «Открыть папку результатов»** после прогона (explorer).

## Этап 4 — Аналитические возможности (v1.5+)

Требуют абстракции в `phyml_core` — движок как интерфейс.

4.1 **IQ-TREE как второй движок:** выбор в поле «движок», автоподбор
    модели (ModelFinder), UFBoot2 + aLRT одновременно; парсинг его
    `.iqtree`/`.treefile` в те же структуры результатов.
4.2 **Таблица статистики:** все прогоны из истории — lnL, число
    параметров, AIC/BIC (где доступно), время; сравнение строк,
    сортировка; для IQ-TREE — топ-модели из ModelFinder.
4.3 **Предпросмотр выравнивания** перед запуском: число таксонов, длина,
    доля гэпов, консенсус-строка; предупреждение о подозрительных ID
    до санитарной очистки.
4.4 **Экспорт XLSX** (openpyxl) рядом с CSV: сводка + лист статистики
    + лист истории — одним файлом отчёта.

## Этап 5 — Инфраструктура (параллельно, вклинивать между этапами)

5.1 **Тесты в репозиторий:** перенести `testrun/`-наборы в `tests/`,
    pytest + фикстуры; тестовые данные генерируются кодом (уже так).
5.2 **CI (GitHub Actions, windows-latest):** прогон тестов на каждый
    пуш; по тегу `v*` — сборка exe, zip с phyml-mpi и авто-релиз.
5.3 **CLI-режим:** `phymlgui --batch <папка> --config <preset.json>` —
    тот же пайплайн без GUI (ядро уже отделено, остаётся обёртка).
5.4 **Автопроверка обновлений:** запрос последнего релиза через GitHub
    API, ненавязчивое уведомление при старте (опционально, off по умолчанию).
5.5 **MUSCLE в релизном zip:** добавить `muscle.exe` рядом с
    `phyml-mpi.exe`, чтобы типичная установка была «распаковал и работает».

## Идеи на дальнюю полку

- Консенсус-дерево из бутстреп-файлов PhyML прямо в GUI.
- Сравнение топологий двух деревьев (Robinson–Foulds, общий поддеревовый экран).
- Запуск на удалённой машине/кластере по SSH (очередь + забор результатов).
- Веб-версия интерфейса (отдельное решение по стеку).
